**DeadlockBehavior — project and pipeline audit, September 12, 2026**

The project already has a functioning replay extraction pipeline and a substantial authority framework. A fresh isolated run of `104373259.dem` completed all ten production stages in **211.268 seconds**, producing a manifest with **108/108 A metrics: 99 core and 9 extended**. The resulting model contains twelve players and production melee data for all twelve.

That result establishes producer coverage for this replay. It does not establish that every displayed value is correct, available, or properly scoped. The audit reproduced errors in time accounting, missing-data presentation, readiness detection, and a primary-fire display connection. Reliability should be the next milestone before expanding the A set.

No application source, contracts, or existing production outputs were changed. Test fixtures and the fresh pipeline output were generated separately; ordinary test execution also uses derived caches. This report and its companion JSON files are outside the project directory.

**Project scope and architecture.** The repository contains 270 files in `scripts/`, including many historical versions of research experiments. `src/` supplies reusable claim, resource, weapon-state, and diagnostic logic. `contracts/claim_registry_v03.json` records 67 claims: 53 current, seven provisional, four withdrawn, and three missing. The canonical production contract defines which inspector metrics receive A status. A and B describe authority/production eligibility, not statistical complexity.

The active visualizer is `inspector-v04/`: a Node HTTP server, replay model builder, production orchestrator, and three browser modules (`app.js`, `authoritative.js`, and `workspace.js`). The older `inspector/` and patch directories preserve earlier implementations. There is no need to replace the project or convert every historical research script into production processing.

The operational sequence is replay import or directory detection → explicit pipeline → per-replay JSON/JSONL artifacts → production manifest → replay model/cache → visualizer. The ten stages cover player state, Trooper deaths, Ground Soul lifecycle, Ground Soul economic credit, health regeneration, item ownership, permanent buffs, bridge buffs, primary fire, and melee. Several stages depend on shared validated artifacts in `output/cross_replay/`; the successful clean run retained those shared inputs but started with no outputs for the target replay.

**The following findings are ordered by their effect on trustworthy automatic statistics.** “Reproduced” means executed against real artifacts or a small isolated fixture; other findings are identified from the implementation.

1. **Pregame time contaminates A aggregates — reproduced.** The fresh model reports 2,567.75 match seconds, while each player's alive-plus-dead time totals 2,597.5 seconds, a 29.75-second excess. `updatePlayer` integrates demo-time differences before gameplay begins and chooses the first pregame state as the initial baseline. This affects alive/dead duration, alive share, life intervals, health-threshold integration, and potentially growth-rate baselines. Primary-fire extraction also includes pregame events and integrates pregame alive time. Establish explicit replay-time versus gameplay-time scopes and use one interval implementation across producers and model formulas. [Model integration](G:/DeadlockBehavior/inspector-v04/lib/replay-model.mjs:180), [primary-fire producer](G:/DeadlockBehavior/inspector-v04/production/extract-runtime-primary-fire.mjs:169).

2. **Wired and available are conflated — reproduced.** In the existing `104373259` output, the melee production artifact is absent, yet the actual Authoritative Stats renderer returns `wired: true` and zero melee attacks/hits. The “108/108 wired” badge counts display cases, regardless of source availability or run validity. Items, buffs, and some other cards also use empty/zero defaults. Return availability separately from value; a missing producer result must not imply a measured zero. Each stat needs its replay/run identity, source, availability reason, and authority scope. [Coverage calculation](G:/DeadlockBehavior/inspector-v04/public/authoritative.js:91), [melee defaults](G:/DeadlockBehavior/inspector-v04/public/authoritative.js:235).

3. **Readiness does not identify stale or invalid results robustly — reproduced.** The existing manifest for `104373259` covers 77 A stats. Inventory correctly calls it `STALE_CONTRACT`, but automatic ingestion returns `already_processed`. The other six replay files have research outputs but no production manifest and are classified `UNPROCESSED`. Readiness compares contract counts, not contract contents, and trusts stored completion totals without checking output files. A synthetic COMPLETE manifest with 108/108 counters and no output artifacts was accepted as READY. Fingerprint the replay, contract, producer versions, and shared resource inputs; validate output availability and stage ownership. Failed/stale runs need an explicit retry policy. [Readiness and ingestion decision](G:/DeadlockBehavior/inspector-v04/lib/replay-readiness.mjs:50).

4. **Next-primary-ready has a broken production schema connection — reproduced.** Production events contain top-level `nextPrimaryAttack`. `latestNextPrimaryReady` searches only legacy nested fields. On real rows it returned null although the last relevant value was `2556.963623046875`. This was the only unavailable value in the final-time renderer probe for renso after the fresh run. Use the production schema or the existing model summary, and distinguish latest-in-replay from state-at-selected-time. [Display loader](G:/DeadlockBehavior/inspector-v04/public/authoritative.js:298), [production event structure](G:/DeadlockBehavior/inspector-v04/production/extract-runtime-primary-fire.mjs:93).

5. **Player names are used as primary identity — reproduced.** Two distinct controllers/Steam IDs with the same display name become one player in the replay model. Names also drive selection and many evidence joins. Use stable replay-local controller identity plus Steam identity where available, tracking pawn changes separately. This is necessary before cross-match behavior tracking. [Identity key](G:/DeadlockBehavior/inspector-v04/lib/replay-model.mjs:181).

6. **Clock and checkpoint boundaries remain inconsistent — reproduced.** Team-series ticks retain a hard-coded 30-second offset: a fixture with offset 10 produced tick 1920 at match time zero instead of 640. A ten-second fixture also received every checkpoint through 50 minutes, repeating its last available state. The match clock is A through the tick-rate claim, while the dedicated 30-second clock-offset claim remains provisional; tick-rate authority alone does not resolve clock-origin semantics. Native postgame timing is exposed when legacy integrated data exists but is not the model's duration boundary. Keep observed replay duration and competitive gameplay duration explicit rather than silently changing a denominator. [Team ticks and checkpoints](G:/DeadlockBehavior/inspector-v04/lib/replay-model.mjs:525), [claim registry](G:/DeadlockBehavior/contracts/claim_registry_v03.json).

7. **Evidence connections lag promotions — code confirmed.** The melee API still reads `verified_melee_events.jsonl` instead of `runtime_melee_events_v01.jsonl`. Scoreboard cards request evidence kind `scoreboard`, which is absent from the server's evidence map. Source Health omits the runtime melee artifacts. Authoritative cards show source text but do not provide a complete per-metric evidence contract. Wire metric → producer → model field → evidence route → renderer explicitly and test that entire chain. [Evidence map](G:/DeadlockBehavior/inspector-v04/server.mjs:129), [source health](G:/DeadlockBehavior/inspector-v04/lib/io.mjs:23).

8. **Caches and partial runs can preserve obsolete values — code confirmed.** Disk fingerprints use input file paths, sizes, and mtimes, with no model-code or contract version check. Several consumed research inputs are absent from the fingerprint list. In-memory promises can retain a model until explicit invalidation. Producers overwrite outputs in place, so an interrupted run can leave new core data beside old successful optional artifacts; the model is not gated on one coherent run manifest. Use an isolated run directory, validate it, then atomically publish its manifest and outputs. Make cache identity depend on the published run and model schema. [Cache acceptance](G:/DeadlockBehavior/inspector-v04/lib/replay-model.mjs:10), [pipeline writes](G:/DeadlockBehavior/inspector-v04/lib/pipeline.mjs:152).

9. **Integrity checks are uneven — code confirmed.** The orchestrator verifies child exit and fresh output size/mtime, not every artifact schema or every metric value. Core extraction lacks the richer coverage gates used by newer producers. JSONL readers silently skip malformed rows, while Source Health only reports file existence/size. Numeric helpers in model/UI turn null into zero via `Number(null)`, and missing scoreboard counters default to zero. Introduce counted parse errors, explicit nullable numeric conversion, per-player field coverage, and schema/invariant validation before a run can be READY. [Reader behavior](G:/DeadlockBehavior/inspector-v04/lib/io.mjs:9), [core normalization](G:/DeadlockBehavior/inspector-v04/lib/replay-model.mjs:301).

10. **Deployment and scaling contracts are incomplete — code confirmed, broader impact not benchmarked.** Resource-dependent stages load frozen catalogs/validation artifacts from research output paths. They validate catalog structures and known hashes, but do not provide a general replay-build compatibility gate. Startup ingestion can launch several replays concurrently; there is no global queue limit, stage timeout, durable job state, or resumable run. Upload buffers up to 1 GiB and saves directly to the destination name. The fresh model response was about 23.4 MB; Authoritative Stats fetches the model and scans weapon evidence again when rendered. These are manageable locally but need bounded jobs, atomic import, compact time-series queries, and durable progress for routine ingestion. [Server](G:/DeadlockBehavior/inspector-v04/server.mjs), [auto-ingestion](G:/DeadlockBehavior/inspector-v04/lib/replay-auto-ingestion.mjs).

**Recommended next implementation milestone:** make one imported replay produce a coherent, current, trustworthy 108-stat result. First fix time accounting, missing-data semantics, identity, and the confirmed display/evidence bugs. Then add run fingerprints, atomic publication, versioned caches, and bounded processing with useful progress. Finally execute the complete pipeline across the seven-replay corpus, add targeted failure fixtures, and verify actual UI values at selected times. After this milestone, promote B families one at a time, beginning with the Ground Soul resolver review.

A useful completion condition is: every A metric resolves to either a validated value or an explicit unavailable/not-applicable reason; no missing source becomes zero; the UI and export use the same metric computation; evidence references the same replay/run; time-dependent values use observations at or before the requested instant; stale inputs cannot retain READY status. The current API exposes a nested match model, not a complete versioned metric-value dataset for future monitoring. A stable export with metric IDs, player IDs, time scope, provenance, and missingness will bridge this project to behavioral analysis. Prediction work also needs split-by-player/match/build evaluation and an explicit separation between retrospective final-match summaries and features available at prediction time.

Inspector tests: all 87 passed with an isolated cache directory. Its default-cache API smoke run initially returned HTTP 500; the isolated-cache rerun passed, so this is recorded as a cache/environment interaction rather than a proven model/API logic failure. An initial combined test invocation also exposed working-directory assumptions in inspector tests; suites were subsequently run from their intended directories.

The audit executed one complete fresh real-replay pipeline, rebuilt models from existing real outputs, checked all A claim/display mappings, and ran focused timing, duplicate-name, missing-source, readiness, and renderer probes. It inspected saved cross-replay research validations but did not rerun every historical experiment. It did not perform interactive browser visual QA or establish compatibility with unseen game builds. The successful one-replay run therefore supports current pipeline operability, not universal replay compatibility or blanket numerical correctness.
